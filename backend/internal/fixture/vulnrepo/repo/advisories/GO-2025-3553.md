# GO-2025-3553

Also tracked as CVE-2025-30204 and GHSA-mh63-6h87-95cp.

## Summary

`github.com/golang-jwt/jwt` allocates excessive memory while parsing the header of a
token. A caller that parses untrusted tokens, as this service does on `/verify`, can be
made to allocate far more memory than the token size justifies.

## Affected versions

| Module | Affected | Fixed in |
|---|---|---|
| `github.com/golang-jwt/jwt` | every version, including `v3.2.2+incompatible` | no fix is published for this module path |
| `github.com/golang-jwt/jwt/v4` | before 4.5.2 | 4.5.2 |
| `github.com/golang-jwt/jwt/v5` | 5.0.0-rc.1 and later, before 5.2.2 | 5.2.2 |

## Status of this service

`go.mod` requires `github.com/golang-jwt/jwt v3.2.2+incompatible`, which is affected. The
service calls `jwt.ParseWithClaims` on every `/verify` request, so the vulnerable code
path is reachable.

## Remediation

Move to a module path that has a fixed release. The project rules in `RULES.md` require
the latest major version that the internal mirror serves. Later major versions of this
library changed its API: `StandardClaims` and `ValidationError` no longer exist, so the
calling code must be adapted, not only the module version.
